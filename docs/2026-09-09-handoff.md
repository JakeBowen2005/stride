## What Is Stride

Stride is a personal AI-powered running coach built by Jake Bowen (CS junior at CSUF, 2:58 marathoner, targeting sub-17 5K). It is a full-stack web app that:

- Syncs running history from Strava via OAuth
- Generates personalized 2-week rolling training plans using VDOT pacing methodology
- Tracks workout progression through 12-level ladders (threshold + intervals)
- Provides science-backed post-run feedback via Claude Haiku
- Adapts the plan in real-time based on feedback (feel ratings, swapped workouts)

It is built for Jake first, but designed to scale to other users. The core loop:
**Onboard → Sync Strava → Set Goal → Generate 2-Week Plan → Run → Log Feedback → AI Adjusts Plan → Repeat**

## How the Key Systems Work

### Plan Generation (`backend/app/core/plan_engine.py`)

1. Called from `POST /api/plans/{user_id}/generate`
2. Reads athlete analysis (current weekly mileage, peak mileage, experience level)
3. Reads calibrated paces from recent Strava workout descriptions
4. Reads current workout progression state (what level is the athlete on each ladder)
5. Generates 2-3 weeks depending on day of week (Mon-Wed = 2 weeks, Thu-Sun = 3 weeks)
6. Default structure: Mon easy, Tue workout (intervals), Wed easy, Thu workout (threshold), Fri rest, Sat long run, Sun easy
7. Workouts come from the ladder system (level-appropriate) rather than random templates

### Workout Progression Ladders (`backend/app/core/workout_ladders.py`)

Two 12-level ladders:
- **Threshold ladder**: Starts at 2x10min hard, builds to 5x10min → continuous tempo → 40min tempo
- **Intervals ladder**: Starts at 4x800m, builds through 5x800, 6x800, 5x1K, 4x1mi, 5x1mi, etc.

Each level defines structure (reps, duration, rest) — paces are injected at generation time from calibrated data, not hardcoded.

**Progression state** is stored in `workout_progressions` table per user per category. Starting level is auto-detected from recent Strava descriptions.

### Workout Evaluator (`backend/app/core/workout_evaluator.py`)

Runs when feedback is submitted for a `type == "workout"` day. Logic:

1. Parses split times from Strava description (e.g. `6x800 (3:01, 3:04, 3:02, 3:05, 3:03, 3:04)`)
2. Calculates: pace vs prescribed, rep count vs prescribed, fade (second half minus first half)
3. Combines with feel rating (1-10) to produce a decision:
   - **ADVANCE**: hit paces + feel 7+, low fade → move to next ladder level
   - **RECALIBRATE**: beat paces by 10+ sec/mi + feel 7+ → bump pace targets, advance level
   - **REGRESS**: missed paces badly OR feel ≤4 OR big fade → step back one level
   - **HOLD**: everything else → repeat current level

### AI Coach (`backend/app/services/coach.py`)

Called after every feedback submission. Uses structured context injection (not vector RAG):

1. Always loads: `training-principles.md` + `athlete-profile-jake.md`
2. Goal-specific: loads `5k-training-science.md` (or equivalent for other distances)
3. Recent training: last 14 days of activities (miles, pace, HR, feel)
4. Today's context: what was prescribed, what was done, feel rating, pace assessment
5. Calls Claude Haiku with max 300 tokens → returns 2-4 sentence coaching response
6. Falls back to template responses if no Anthropic API key is set

### Feedback Loop (`POST /api/plans/{user_id}/feedback/{date}`)

Submitting feedback does several things at once:
1. Saves feel_rating, pace_assessment, swapped flag to `planned_workouts`
2. Saves feel_rating to the matched `activity` record
3. Calls coach AI → stores response in `planned_workouts.coach_response`
4. If `type == "workout"` and not swapped: runs workout evaluator, updates progression state
5. If swapped + user wants a hard workout rescheduled: finds a safe gap day and generates a new ladder workout for it
6. If feel_rating ≤ 4 and not swapped: automatically downgrades the next hard day to easy

### Multi-Activity Aggregation

When multiple Strava activities are recorded on the same day (warmup + workout + cooldown as separate segments), the plan view aggregates them:
- Total distance = sum of all activities
- Avg pace = total duration / total distance
- HR = weighted average by duration
- Individual activities listed in expanded view

## Data Flow

```
Strava API
    ↓ OAuth + sync
Activities table (SQLite)
    ↓ pace_calibrator.py parses descriptions
Calibrated paces (interval_pace, tempo_pace, easy_pace)
    ↓ + current progression level
plan_engine.py
    ↓ generates
PlannedWorkout records
    ↓ matched to activities by date
Frontend plan view
    ↓ user submits feedback
workout_evaluator.py + coach.py
    ↓ updates
WorkoutProgression + PlannedWorkout (coach_response, feel_rating, etc.)
    ↓ next plan generation uses updated state
```

## API Endpoints (Backend)

```
GET  /api/strava/connect                    → OAuth redirect URL
GET  /api/strava/callback?code=             → Exchange code, store tokens, create user
POST /api/strava/sync/{user_id}             → Pull all activities from Strava
POST /api/strava/webhook                    → Strava webhook for new activities

POST /api/plans/{user_id}/generate          → Generate new 2-week plan
GET  /api/plans/{user_id}/current           → Active plan with actuals matched
GET  /api/plans/{user_id}/goal              → Active goal
POST /api/plans/{user_id}/feedback/{date}   → Submit post-run feedback

GET  /api/analysis/{user_id}/activities     → Paginated activity list
GET  /api/analysis/{user_id}/weekly-mileage → Mileage by week (for charts)
POST /api/analysis/{user_id}/classify       → Re-classify all activities by type
POST /api/analysis/{user_id}/detect-prs     → Detect personal records
POST /api/analysis/{user_id}/full-sync      → Full re-sync + classify + PRs

POST /api/users/{user_id}/goal              → Set active goal
PUT  /api/users/{user_id}                   → Update user settings
```
